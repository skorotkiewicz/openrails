OpenRails SDK demo

Real SDK calls. Your project key stays on the Node server.

Checking connection…

Explore collections, disk-backed files, SQL and your local model. Each button calls openrails on the demo server. Nothing is seeded or sent to the model automatically.

Collections

CRUD in demo_tasks. Seed replaces only sample-a, sample-b and sample-c.

Filtering and pagination

All filter operators, key prefixes, ordering and timestamp bounds.

Files

Names are prefixed with demo/. Uploads are limited to 16 MiB; downloads stream from disk.

SQL and saved queries

Read-only SQL uses the project's own database. Seed the collection first to see rows.

Local LLM

Uses the model configured for your project on OpenRails. Click llmProviders() to inspect available models, or leave the model override blank to use the project's default.

NDJSON is currently buffered by the backend until one completion finishes. JSON output and tool calls depend on the model. The only executable demo tool is arithmetic; it cannot access files or secrets.

Message-array input

Roster and read-only scopes

appUsers() reads config, not a login database. Scopes stay empty unless you import scoped rows offline.

HTTP connectors

The included models connector lists models on your local LLM. Origins and allowed methods are controlled by server config.

Email

Not configured by default. No real email is sent unless you add an email provider to the demo project. The button will otherwise show 501.

Runtime and response helpers

Standalone context has no authenticated user. Environment access is server-side; secret values are never shown here.

Reserved agent APIs

Shown for completeness. The current backend does not execute agents or MCP connector tools; these calls return 501, not pretend results.

Local development only. No browser API key, framework, CDN, or cloud model required.
